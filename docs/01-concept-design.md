# 01. 기획과 디자인

## 1. 목표와 원칙

방문자가 5초 안에 "누가 어떤 작업을 했는지"를 이해하고, 스크롤하는 동안 작업 이미지를 크게 보게 한다.

1. **글자가 주인공이다.** 화면 폭을 거의 채우는 큰 제목과 넉넉한 여백.
2. **이미지는 크게, 잘리지 않게.** 가로 전체 폭 또는 큰 인셋. 원본 비율을 유지한다.
3. **움직임은 조용하게.** 짧고 부드럽게, 내용을 가리지 않는다. 모션 줄이기 설정을 존중한다.
4. **빠르다.** 기능보다 로딩 속도가 먼저다. 속도 예산은 02번 문서에 있다.
5. **데이터가 곧 콘텐츠다.** 새 작업은 파일 하나를 추가하는 것으로 끝난다.

## 3. 정보 구조

모든 경로는 한글(기본)과 영문(`/en/` 접두어) 두 벌이다. 규칙은 [06번 문서](06-i18n.md).

| 경로 | 내용 |
|---|---|
| `/` | `iduk` 큰 글자 워드마크, 대표 작업 6~8개를 큰 이미지 행으로 |
| `/work/` | 전체 작업 목록. 연도별 그룹, 태그 필터. 데스크톱은 이름에 마우스를 올리면 큰 미리보기 |
| `/work/[slug]/` | 제목, 기간과 역할, 대표 이미지, 이미지 연속 배치, 데모 링크, 이전과 다음 작업 |
| 연락 | **없음.** 개인정보를 공개하지 않는다([07번](07-privacy.md)). 필요해지면 2단계 문의 폼 |
| `/html/*` | 기존 HTML 데모. 주소를 그대로 유지한다 |
| 404 | 큰 글자 안내와 홈 링크 |

기존 주소 `/portfolio/[slug]/`는 `/work/[slug]/`로 영구 이동(301)시킨다. 숫자로만 된 슬러그 `1812`는 `jejuair-mobile`로 바꾸고 옛 주소에서 이동시킨다.

### 작업 상세 화면

- 제목은 한 줄 또는 두 줄의 큰 글자. 아래에 기간, 역할, 태그를 작은 글자 표로 둔다.
- 이미지는 위에서 아래로 한 장씩 크게. 가로형은 전체 폭, 모바일 화면 캡처는 두세 장을 나란히.
- **긴 화면 캡처**(24장)는 전용 컴포넌트로 보여 준다. 브라우저 틀 안에 고정하고, 스크롤할 때 이미지가 위로 흘러가게 한다. 세로 8000px이 넘는 캡처를 그대로 늘어놓는 것보다 훨씬 보기 좋다.
- 하단에 이전 작업과 다음 작업을 큰 글자로 연결한다.

## 4. 타이포그래피

글꼴은 **Pretendard Variable**(라이선스 OFL 1.1, npm 패키지 pretendard 1.3.9)을 자체 호스팅한다. 전체 글꼴 파일은 크므로 유니코드 범위로 쪼갠 동적 서브셋을 쓴다. 외부 글꼴 서버에는 연결하지 않는다.

| 역할 | 크기 | 굵기 | 행간 | 자간 |
|---|---|---|---|---|
| 히어로 | `clamp(3.25rem, 1rem + 10vw, 11rem)` | 800 | 0.92 | -0.045em |
| 작업 제목 | `clamp(2.5rem, 1rem + 6vw, 7rem)` | 700 | 0.98 | -0.035em |
| 소제목 | `clamp(1.75rem, 1rem + 2.5vw, 3.5rem)` | 600 | 1.1 | -0.025em |
| 본문 | `clamp(1rem, 0.95rem + 0.25vw, 1.1875rem)` | 400 | 1.7 | 0 |
| 라벨, 메타 | 0.8125rem | 500 | 1.4 | 0.02em |

- 한글 제목은 `word-break: keep-all`과 `text-wrap: balance`로 단어 중간에서 끊기지 않게 한다. 본문은 `text-wrap: pretty`.
- 숫자와 연도는 `font-variant-numeric: tabular-nums`.
- 본문 한 줄 길이는 약 36em 이하.

## 5. 색

| 토큰 | 밝은 테마 | 어두운 테마 | 용도 |
|---|---|---|---|
| 바탕 | `#FAFAF8` | `#0E0E0E` | 페이지 배경 |
| 글자 | `#111111` | `#F2F2EE` | 본문, 제목 |
| 보조 글자 | `#6B6B66` | `#9A9A94` | 메타, 캡션 |
| 포인트 | `#D93036` | `#F97272` | 링크, 강조 |

포인트 색은 기존 사이트의 산호색 `#F97272`에서 가져왔다. 밝은 배경에서는 이 색의 대비가 2.62:1로 글자에는 쓸 수 없어서 어둡게 보정했다.

| 조합 | 대비 | 판정 |
|---|---|---|
| `#F97272` 위 `#FAFAF8` | 2.62 | 글자 불가 |
| `#D93036` 위 `#FAFAF8` | 4.54 | 본문 글자 가능 |
| `#F97272` 위 `#0E0E0E` | 7.06 | 가능 |

작업 이미지는 각자 평균색을 JSON에 기록해 두고, 이미지가 로드되기 전에 그 색을 배경으로 보여 준다. 흰 화면에서 이미지가 불쑥 나타나는 느낌을 줄인다.

## 6. 레이아웃과 반응형

- 모바일 우선. 기준 폭은 640, 1024, 1440, 1920px.
- 12열 격자. 좌우 여백은 `clamp(1.25rem, 4vw, 4rem)`. 이미지는 여백을 무시하고 가로 전체 폭을 쓸 수 있다.
- 구역 사이 간격은 `clamp(4rem, 2rem + 8vw, 10rem)`.
- 카드는 컨테이너 쿼리로 자기 폭에 맞춘다.
- 터치 대상은 44px 이상. 호버에만 의존하는 정보는 두지 않는다.
- `sizes` 속성을 정확히 지정해 모바일이 큰 이미지를 받지 않게 한다.

## 7. 움직임

| 항목 | 값 |
|---|---|
| 곡선 | `cubic-bezier(0.22, 1, 0.36, 1)` |
| 시간 | 짧게 160ms, 보통 320ms, 길게 640ms |

| 동작 | 구현 |
|---|---|
| 스크롤 등장 | 아래에서 24px 올라오며 투명도 0에서 1, 640ms. CSS `animation-timeline: view()` |
| 히어로 문구 | 줄 단위로 가려졌다 열리는 효과, 800ms |
| 이미지 호버 | 1.03배 확대, 640ms |
| 페이지 이동 | 브라우저 기본 교차 문서 전환, 320ms 교차 페이드 |
| 목록에서 상세로 | 같은 이미지가 이어지는 공유 요소 전환 |

- 스크롤 애니메이션과 페이지 전환은 지원하는 브라우저에서만 적용한다. 지원하지 않는 브라우저는 요소가 즉시 보이고 일반 이동으로 동작한다.
- Astro의 ClientRouter는 쓰지 않는다. Astro의 CSP 기능이 ClientRouter를 지원하지 않기 때문이다.
- 부드러운 스크롤 라이브러리(Lenis 등)는 처음에는 넣지 않는다. 번들이 늘고 접근성 문제를 만들기 쉽다. 쓰고 싶다면 4단계 마감에서 효과를 비교해 결정한다.
- `prefers-reduced-motion: reduce`에서는 이동과 확대를 모두 끄고 120ms 이하의 투명도 변화만 남긴다.

## 8. 접근성 기준

- WCAG 2.2 AA를 기준으로 한다.
- 대비 4.5:1 이상, 키보드로 모든 기능 접근, 눈에 보이는 포커스 링, 본문으로 건너뛰기 링크.
- 페이지 언어에 맞는 `lang`(`ko` 또는 `en`). 제목 계층을 지킨다.
- 이미지는 `alt`가 필수다. 기존 본문 이미지는 `alt`가 비어 있는 경우가 많다(예: JEJUair 글). 작업 제목과 화면 이름으로 채우고, 장식 이미지는 빈 `alt`로 둔다.
- 자동 점검은 axe, 수동 점검은 키보드와 화면 낭독기.

## 10. 글 쓰기 흐름

새 작업은 `src/content/projects/<slug>.json` 파일 하나와 이미지 몇 장을 추가하면 된다. 필드가 빠지거나 이미지 경로가 틀리면 빌드가 실패해서 잘못된 글이 공개되지 않는다.
