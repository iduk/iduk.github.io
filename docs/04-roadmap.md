# 04. 구현 로드맵

작업일은 한 사람이 AI와 함께 진행하는 것을 가정한 추정이다. 사용자의 결정과 문구 작성에 걸리는 시간은 포함하지 않는다.

| 단계 | 내용 | 추정 |
|---|---|---|
| 0 | 준비와 계정 보안 | 0.5일 |
| 1 | 콘텐츠 변환 | 1~1.5일 |
| 2 | 프로젝트 기반 | 1일 |
| 3 | 페이지와 컴포넌트 | 3~4일 |
| 4 | 다듬기와 검증 | 1~2일 |
| 5 | 공개와 도메인 전환 | 0.5일 |
| 합계 | | 약 9~10일 (한글·영문 병행 포함, [06번](06-i18n.md)) |
| 6 (나중) | Neon: 문의와 반응 | 2~3일 |

## 단계 0. 준비

작업
- [README의 7가지 결정](README.md#먼저-정해야-할-것)을 정한다.
- [보안 문서 3절](03-security.md#3-전환-전에-끝낼-일)의 계정 정리를 끝낸다.
- 기존 저장소 정리: main의 옛 코드에 `legacy-react-2022` 태그를 붙이고, 외부 웹훅과 GitHub Pages를 끈다.
- 도메인 등록처와 DNS는 Cafe24로 확인됨(메일 미사용). DNS 레코드 편집 화면 위치를 확인한다.

완료 기준: 모든 계정에 2단계 인증, 옛 비밀번호 폐기, 결정 사항이 문서에 기록됨.

## 단계 1. 콘텐츠 변환

작업
- 변환 스크립트를 만든다([02번 문서 5절](02-architecture.md#5-콘텐츠-파이프라인)).
- 60장(대표 + 본문 이미지)을 WebP(화질 90, 가로 2560px 이하)로 변환하고 `images.json`을 만든다.
- 글 41개를 새 스키마로 변환하고 정화한다. 34개는 자동, 7개는 수동.
- 리다이렉트 표, HTML 데모, PDF를 옮긴다.
- 2019년 버전 본문 중 현재 본문보다 나은 것을 골라 반영한다.
- 이미지마다 `alt`를 채운다.

완료 기준
- 스키마 검증 통과, 깨진 이미지 참조 0, 옛 사이트 주소 0, 빈 `alt` 0.
- 저장소 이미지 용량이 약 25MB 이하.
- 공개 글 24개가 모두 변환되어 화면 확인을 마쳤다.

## 단계 2. 프로젝트 기반

작업
- Astro 7 프로젝트를 만들고 pnpm 12로 고정한다. `pnpm-workspace.yaml`의 보안 설정을 넣는다.
- Tailwind 4 토큰(색, 글자 크기, 간격, 움직임)과 Pretendard 서브셋을 설정한다.
- 기본 레이아웃, 머리말, 꼬리말, 다크 모드.
- `vercel.json`에 보안 헤더와 리다이렉트를 넣는다. `security.csp`를 켠다.
- Biome, `astro check`, Vitest, Playwright, axe를 설정하고 CI를 만든다. Lighthouse 예산 검사를 넣는다.
- 은폐 검사 예약 워크플로를 만든다.

완료 기준: 빈 페이지가 CI를 통과하고 Vercel 미리보기에 올라간다. 보안 헤더가 응답에 붙는다.

## 단계 3. 페이지와 컴포넌트

작업 순서
1. `Picture` 컴포넌트: AVIF와 WebP, `sizes`, 평균색 배경, 가로와 세로 고정.
2. 작업 상세 `/work/[slug]/`: 제목, 메타 표, 이미지 블록, 이전과 다음.
3. `LongShot` 컴포넌트: 긴 화면 캡처 24장.
4. 작업 목록 `/work/`: 연도별 그룹, 태그 필터, 호버 미리보기.
5. 홈 `/`: 히어로와 대표 작업 행.
6. 404. (About·Contact 페이지와 연락처는 만들지 않는다)
7. 움직임: 스크롤 등장, 히어로 문구, 이미지 호버, 페이지 전환, 모션 줄이기 대응.
8. HTML 데모 연결과 CSP.
9. 메타 태그, 열린 그래프 이미지, 사이트맵, robots.txt, 구조화 데이터.

완료 기준
- 모든 화면이 360, 768, 1280, 1920px에서 깨지지 않는다.
- 첫 측정에서 [성능 예산](02-architecture.md#7-성능-예산)에 얼마나 못 미치는지 기록한다.
- 이 단계에서 Astro와 Next.js의 실제 번들 크기를 같은 화면으로 비교할 필요는 없다. 예산을 못 맞추면 그때 판단한다.

## 단계 4. 다듬기와 검증

작업
- 성능: Lighthouse 모바일 95 이상, LCP, CLS, INP 예산 달성.
- 접근성: axe 자동 검사, 키보드만으로 전체 순회, 화면 낭독기 확인, 모션 줄이기 확인.
- 브라우저: 최신 Chrome, Safari(iOS 포함), Firefox. 페이지 전환과 스크롤 애니메이션은 미지원 브라우저에서 정상 동작하는지 본다.
- 실제 휴대폰에서 확인한다.
- 문구와 이미지 `alt`를 다듬는다.
- 부드러운 스크롤 라이브러리가 필요한지 판단한다.

완료 기준: 위 예산과 접근성 기준 충족, [보안 점검 목록](03-security.md#8-공개-후-점검-목록)의 공개 전 항목 통과.

## 단계 5. 공개와 도메인 전환

1. Vercel에 프로젝트를 만들고 미리보기에서 최종 확인한다.
2. 24시간 전에 DNS TTL을 낮춘다.
3. Vercel에 `iduk.co.kr`과 `www.iduk.co.kr`을 추가하고 안내된 A/CNAME 레코드로만 바꾼다. 네임서버는 Cafe24 그대로 둔다.
4. HTTPS 인증서 발급, 옛 주소 리다이렉트, `robots.txt`, 사이트맵을 확인한다.
5. 구글 서치 콘솔: 사이트맵 제출, 남아 있는 스팸 주소 삭제 요청, 보안 문제 항목 확인.
6. 은폐 검사를 처음 실행한다.
7. 2주 동안 지켜본 뒤 [옛 사이트 정리](03-security.md#7-옛-사이트-정리)를 한다.

되돌리는 방법: DNS를 옛 호스팅으로 되돌린다. 단, 옛 호스팅은 감염 상태이므로 임시로만 쓰고 가능하면 안내 페이지만 올려 둔다.

## 단계 6. Neon (나중)

- 문의 폼과 작업별 반응을 만든다([02번 문서 9절](02-architecture.md#9-2단계-neon)).
- `@astrojs/vercel` 어댑터를 추가하고, 해당 경로만 요청 시 실행으로 둔다. 나머지는 정적으로 유지한다.
- 보안 문서 4.6절의 통제를 모두 적용한 뒤에 공개한다.
- 시작 전에 Neon 무료 플랜 한도와 Vercel 함수 한도를 다시 확인한다.

## 범위 밖

관리자 화면, 댓글, 블로그, 제3의 언어, 사용자 로그인, 검색. 필요해지면 따로 계획한다.

## 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 공개 저장소에 비공개 자료가 섞임 | 비공개 글·접속 정보 노출 | 변환 결과만 커밋하고 `git grep` 검사를 푸시 전 필수 단계로 |
| 옛 글 구조가 예상보다 불규칙함 | 변환 시간 증가 | 자동 변환 실패분은 수동으로 처리. 7개는 처음부터 수동으로 잡았다 |
| AVIF 빌드가 느림 | 배포 대기 | WebP로 시작하고 AVIF는 나중에 추가 |
| CSP가 일부 데모를 깨뜨림 | 데모 화면 오류 | `/html/*`에 별도 정책을 두고 콘솔로 필요한 호스트만 허용 |
| Hobby 플랜의 비상업 조건 | 계정 정지 가능성 | 용도를 확인하고, 영업용이면 Pro로 전환 |
| 호스팅 해지 시 Cafe24 DNS 레코드 소실 | 새 사이트 접속 불가 | 해지 전에 네임서버 서비스 유지 여부를 확인하고, 변경 전에 현재 레코드를 기록 |
| 구글에 옛 스팸 주소가 남음 | 검색 노출 저하 | 사이트맵 제출, 삭제 요청, 방화벽 차단 |
| 프레임워크 선택 후회 | 재작업 | 콘텐츠 JSON과 이미지는 프레임워크와 무관하므로 옮기는 비용이 작다 |
