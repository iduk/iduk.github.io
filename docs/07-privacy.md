# 07. 개인정보 비공개 원칙

결정: **이메일을 포함해 어떤 개인정보도 사이트, 저장소, 문서, 커밋 기록에 공개하지 않는다.** 이 문서는 모든 문서보다 우선한다.

## 1. 공개하지 않는 것

| 분류 | 예 | 처리 |
|---|---|---|
| 연락처 | 메일, 전화, 주소, SNS 계정 | 사이트에 표시하지 않는다. **연락 수단이 없는 사이트로 시작한다.** |
| 신원 | 실명, 경력, 학력, 얼굴 사진 | 이미 쓰지 않기로 했다. 로고는 `iduk` 글자만 |
| 계정 | 로그인 계정명, 서버 주소, FTP 정보, 비밀번호, 토큰 | 저장소에 넣지 않는다 |
| 환경 | 로컬 사용자명이 든 절대 경로(`/Users/...`) | 문서와 스크립트는 상대 경로만 |
| 기록 | Git 커밋 작성자 메일, 파일 메타데이터(EXIF 위치·기기) | 아래 3·5절 |
| 제3자 | 데모와 작업물에 들어 있는 회사 담당자 메일·전화 | 아래 4절 |

## 2. 사이트에서 빠지는 것

- 푸터 메일 링크, Contact 페이지, `mailto:`, `security.txt`의 연락처, JSON-LD의 `Person`·`email`·`sameAs`. 모두 만들지 않는다.
- 푸터에는 `© iduk`와 언어 전환 정도만 둔다.
- 연락 수단이 필요해지면 S16의 문의 폼을 쓴다. 주소를 노출하지 않고 받는다. 이 경우에도 방문자가 입력한 이름·메일은 그 자체가 개인정보이므로, 수집 항목·보관 기간·삭제 방법을 알리는 안내문을 폼과 함께 공개하고, 이 문서를 갱신한다.
- 분석은 쿠키를 쓰지 않는 Vercel Web Analytics만 사용한다(광고·추적 스크립트 없음, 외부 글꼴 서버 없음).

## 3. Git에 남는 개인정보 (가장 놓치기 쉬움)

현재 이 저장소의 커밋 기록 81건이 사용자의 개인 메일 주소를 작성자로 가지고 있다(`git log --format=%ae`로 확인). 이미 공개된 `main` 기록이므로 **사이트에서 메일을 뺀다고 사라지지 않는다.** 앞으로 만드는 커밋은 다음을 따른다.

1. GitHub 설정 → Emails에서 **Keep my email addresses private**와 **Block command line pushes that expose my email**을 켠다.
2. 이 저장소에만 noreply 주소로 설정한다. 주소는 GitHub이 Emails 화면에 보여 준다(`<숫자>+<계정>@users.noreply.github.com`).
   ```bash
   git config user.email "<GitHub이 알려 준 noreply 주소>"
   git config user.name "iduk"
   ```
3. 새 커밋 작성자가 noreply인지 푸시 전에 확인한다: `git log --format='%an <%ae>' origin/..HEAD`.
4. **기존 기록의 메일은 어떻게 하나?** 선택지는 둘이다. 어느 쪽이든 사용자가 정한다.
   - (a) 그대로 둔다. 가장 안전하고 쉽지만, 이미 공개된 메일은 남는다. 메일을 계속 쓰는 계정이라 스팸 노출 정도를 감수.
   - (b) 기록을 다시 쓰고 강제 푸시한다. `git filter-repo --mailmap`으로 작성자를 바꾼다. 저장소를 지웠다 새로 만드는 방법이 더 깔끔하다(새 저장소 이름과 Vercel 연결을 다시 해야 함). 이미 복제·캐시된 사본에는 남고, 되돌릴 수 없는 작업이므로 사용자 확인 후에만 한다.
5. 저장소를 지우고 새로 만드는 경우 `legacy-react-2022` 태그는 만들지 않는다(옛 코드 기록에 메일이 있다). 필요하면 로컬 보관만.

## 4. 데모와 콘텐츠 속 제3자 정보

`iduk.design/html`의 데모 4개를 조사한 결과 다음이 있다.

| 파일 | 내용 |
|---|---|
| `atom/location.html` | 업체 메일 1건, 전화·팩스 번호 |
| `hidea/contact.html` | 예시 메일 1건 |
| `suwon/wpt/user.html` | 공공기관 계정 메일 1건 |
| 다수 | 전화번호 `02-XXXX-XXXX`, `031-XXX-XXXX` 형태 등 (실제 번호일 수 있음) |

- 기본 처리: **복사할 때 메일은 `contact@example.com`, 전화는 `000-0000-0000`으로 바꾼다.** 원본은 `iduk.design`에 그대로 있다. 교체 목록은 저장소 밖 보고서에만 남긴다.
- 이는 "데모를 원본 그대로 둔다"는 이전 계획의 예외다. 회사 정보가 그대로 필요하면 사용자가 그 항목만 허용한다.
- 라이브러리 안의 가짜 값(`010-1234-1234`)은 개인정보가 아니므로 건드리지 않는다. 라이브러리 헤더 주석의 작성자 메일은 교체한다(저장소에 실제 메일 주소를 두지 않는다).
- **실제로 교체하는 것(S09 구현):** 메일, 전화(`+` 없는 국가번호 `82 2 …`, 대표번호 15xx, `T.02-…` 접두, `tel:` 링크, 슬래시 구분 포함), 사업자등록번호(`000-00-00000`), 통신판매업 신고번호(`제0000-0000호`), 인코딩된 `@`(`&#64;`, `%40`). 실명·회사 주소·길 안내 문구는 **저장소 밖** 치환 목록(`$TMPDIR/iduk-redact.json`)으로 바꾸며, 목록이 없으면 `copy-demos`가 실패한다(`--no-redact`로만 건너뛴다).
- **지도:** 구글 지도 임베드의 `pb=` 값은 주소와 정확한 좌표를 담고 있어 `<iframe src>`를 `about:blank`로 바꾸고, 길찾기 링크는 `#`으로 바꾼다.
- **이미지:** 증서(자격, 특허, 등록증), 대표·임직원·행사·언론 사진, 광고 모델 사진, 회사 정보가 글자로 든 이미지는 같은 비율의 자리표시로 바꾼다(`scripts/lib/demos.ts`의 `OMITTED_IMAGES`). 나머지 JPEG·PNG는 재인코딩 없이 EXIF·XMP·텍스트 청크를 뺀다.
- **정리:** 데모 `index.html`에서 링크로 닿지 않는 페이지(템플릿 조각 등)와 어디서도 이름이 언급되지 않는 파일은 복사하지 않는다.
- **검증:** `tests/unit/public-guard.test.ts`가 커밋된 `public/html`, `public/files`를 직접 검사한다.
- **PDF:** 지금 공개하는 PDF는 없다(3개 모두 보류). 문서 속성은 도구가 지우지만 본문 속 글자가 윤곽선·래스터로 들어 있으면 자동 검사가 못 본다. 모든 페이지를 사람이 눈으로 본 뒤에만 올린다.
- **사람이 봐야 하는 것(자동 검사 한계):** 실명, 주소, 사람 얼굴 사진, 그림·윤곽선·래스터로 들어간 글자(이미지 속 번호, PDF 속 연락처)는 패턴으로 잡히지 않는다. 새 데모·이미지·PDF는 사람이 훑어 본 뒤 `OMITTED_IMAGES`, 저장소 밖 치환 목록, `REVIEWED_PDFS`로 반영한다.
- 글 본문과 이미지: 변환 스크립트가 본문에서 메일·전화 패턴을 찾아 보고한다. 이미지 안에 보이는 실명·번호는 자동으로 못 찾으므로, 대표 작업 24개의 이미지를 사용자가 한 번 훑어본다. 비공개 글은 이미 제외다.
- 이미지 메타데이터: 변환 때 모든 EXIF·ICC 외 메타데이터를 제거하고 GPS 포함 여부를 검사한다.

## 5. 도메인 등록 정보

`iduk.co.kr`은 Cafe24 등록이다. `.kr` 도메인의 등록자 정보(이름·메일·전화·주소)는 조회 서비스에 노출될 수 있다.

- Cafe24 도메인 관리에서 **등록자 정보 공개 범위(Whois 공개 설정, 대행 서비스)** 를 확인하고 비공개/대행으로 바꾼다. 가능한 옵션은 화면에 따라 다르므로 S00에서 확인한다.
- 전환 직전에 `whois iduk.co.kr` 또는 KISA 조회로 현재 노출 내용을 캡처해 비교한다.

## 6. 자동 검사

CI(S12)와 푸시 전 점검(S05, S13)에 다음을 넣는다. 하나라도 걸리면 실패한다. 허용 목록은 `scripts/privacy-allow.txt`에 이유와 함께 적는다.

```bash
# 저장소 전체(dist 포함)
git grep -nE "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}" -- . ':!pnpm-lock.yaml' ':!*.md'
git grep -nE "(01[016789]|0[2-6][0-9]?)-?[0-9]{3,4}-?[0-9]{4}" -- src public
git grep -nE "/Users/[a-z]+|C:\\\\Users" -- .
git grep -niE "gmail\.com|naver\.com|kakao|sftp"
# 옛 서버 호스트 이름, 옛 계정 ID 패턴은 저장소에 적지 않는다. 저장소 밖 비공개 목록($IDUK_PRIVATE_PATTERNS, 줄마다 정규식)에서 읽어 같은 방식으로 돌린다
# 빌드 결과
grep -rEn "mailto:|tel:" dist
# 이미지 위치 정보
pnpm check-privacy   # S12부터 위 항목 전부와 이미지 GPS를 한 번에 검사한다(아래)
```

**S12 구현(`scripts/check-privacy.ts`)** `pnpm check-privacy`가 위 항목 전부를 `git ls-files`(추적 파일 + 아직 추가하지 않은 새 파일)와 `dist/`에 돌린다. 종료 코드 0/1이고, 출력에는 일치한 값을 싣지 않는다(파일, 줄, 규칙, 개수만).

- 메일, 전화, `/Users/` 경로, 접속 단어, 비밀 값 패턴은 `scripts/lib/privacy.ts`의 `scanText`를 쓴다. 데모(`public/html`, `dist/html`)는 확장 패턴 `scanDemoText`로 본다. `.map` 파일과 사이트가 만든 JS·CSS의 `sourceMappingURL`, `dist`의 `mailto:`·`tel:`, 이미지 GPS(EXIF·XMP, `src/assets/images`·`public`·`dist` 전부)도 실패 조건이다. 데모 CSS에 박힌 base64 소스맵은 풀어서 같은 패턴으로 본다.
- 허용 목록은 `scripts/privacy-allow.txt`다. 한 줄에 `종류 | 경로 | 일치 값(정확히) | 이유`이고 이유가 없으면 검사가 실패한다. 쓰이지 않는 항목은 경고한다. 일치 값 `*`는 검사기·정화기의 시험 입력을 담은 파일에만 쓴다.
- 옛 서버 호스트·계정 정규식은 저장소 밖 파일(`$IDUK_PRIVATE_PATTERNS`, 줄마다 정규식, `#` 주석)에서 읽어 문서를 포함한 저장소 전체(바이너리는 latin1로)와 `dist/`에 적용한다. 파일 이름에도 적용한다. 환경 변수가 없으면 CI(`CI=true`)에서는 실패하고, 로컬에서는 경고하며 `--require-private`를 주면 실패한다. 포크 PR은 `--allow-missing-private`로 크게 경고하고 넘어간다(docs/05 S12).
- 비공개 글의 제목·슬러그는 원본 아카이브(`../iduk.design`이 이웃 폴더에 있으면 자동, 또는 `--archive 경로`)의 `posts.json`에서 공개 포트폴리오 글이 아닌 글(post)만 메모리로 뽑아 검사한다(제목 4자 이상, 슬러그 5자 이상이며 공개 글·태그 슬러그와 겹치지 않는 것). 워드프레스 고정 페이지(Intro, Contact 등)는 제목이 일반 단어라 뺀다. 아카이브가 없으면(CI) 건너뛴다.
- 데모 치환 원본(`$TMPDIR/iduk-redact.json`, 저장소 밖)이 있으면 그 문자열의 모든 표기 변형이 저장소·`dist`에 없는지도 본다.
- `dist`의 모든 HTML에서 `href`·`src`·`srcset`·`action`·`poster`와 `<link>`의 주소가 실제 파일로 해석되는지(`<base>`, 상대 경로, 슬래시, 쿼리, 사이트 페이지의 `#프래그먼트` 포함, 데모 포함), 사이트 페이지가 외부 자원(스크립트, 스타일, 이미지, iframe)을 부르지 않는지 본다. 외부 링크는 목록만 만들고 요청하지 않는다(`--list-external`).
- `pnpm check-privacy --pre-publish`는 S13·S14 전에 사람이 돌린다. 기본 검사에 더해 `status: draft-translation`이 프로젝트나 태그에 남아 있으면 실패하고, 대표 작업이 6~8개인지, 모든 프로젝트의 태그가 `tags.json`에 있는지, 이미지 alt가 두 언어 모두 비어 있지 않은지 본다. CI는 기본 모드만 쓴다(번역 확인 전에도 녹색이어야 하므로).

- 마크다운(`*.md`)은 위 첫 검사에서 제외하되, 문서에는 메일 형태의 문자열이 없어야 하므로 별도로 `docs/`에도 같은 검사를 돌린다(`@scope/패키지` 표기는 허용 목록).
- 빌드 결과(`dist`)와 소스맵에도 개인정보가 없는지 확인한다. 프로덕션 소스맵은 만들지 않는다(`vite.build.sourcemap: false`).
