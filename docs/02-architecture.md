# 02. 기술 구성

버전은 2026-10-23 기준 npm 최신 안정 버전이다. 프로젝트를 만들 때 다시 조회해서 고정한다.

## 1. 프레임워크 선택

### 후보 비교

| 후보 | 버전 | 성격 | 이 프로젝트와의 적합도 |
|---|---|---|---|
| **Astro** | 7.4.2 | 콘텐츠 중심. 기본은 정적 HTML이고, 필요한 부분만 JS를 얹는 구조 | 가장 높음 |
| Next.js | 16.4.2 | React 앱 프레임워크. 서버 컴포넌트와 서버 렌더링이 기본 모델 | 가능하지만 기능이 과하다 |
| SvelteKit | 3.1.0 | 컴파일 방식이라 번들이 작다 | 좋지만 React 경험을 못 살린다 |
| Nuxt | 4.6.2 | Vue 기반 | 같은 이유로 낮음 |
| React Router | 8.5.0 | React 기반 프레임워크 모드 | 앱에 가깝다 |
| TanStack Start | 1.169.4 | React 기반, 타입 안전 라우팅 | 아직 젊고 콘텐츠 기능이 부족하다 |
| Eleventy | 3.1.7 | 가장 단순한 정적 생성기 | 가볍지만 이미지와 타입 검증을 직접 붙여야 한다 |

### Astro를 고르는 이유

1. **콘텐츠 사이트에 맞다.** 글 24개와 이미지가 전부이고, 상호작용은 메뉴와 필터 정도다. 기본 출력이 JS 없는 HTML이다. 한 2차 출처의 측정에서 같은 내용의 페이지가 Astro는 약 9KB, Next.js는 약 463KB의 JS를 보냈다. 이 수치는 하나의 글에서 나온 것이라 그대로 믿지 않고, 로드맵의 3단계에서 직접 측정한다.
2. **서버 코드가 없다.** 정적 출력이면 요청 시점에 실행되는 코드가 없다. Next.js의 서버 컴포넌트 통신 프로토콜에서는 2025년 12월 미국 CISA가 실제 악용 취약점으로 분류한 원격 코드 실행 취약점(CVE-2025-55182)이 나왔고, 2026년 10월에도 원격 코드 실행 두 건이 포함된 보안 릴리스가 있었다(후자는 2차 출처). 이번처럼 침해를 겪은 사이트는 이런 공격 면적을 처음부터 없애는 쪽이 낫다.
3. **이미지 처리가 내장이다.** 빌드 때 sharp로 크기별 AVIF와 WebP를 만들어 정적 파일로 낸다. 런타임 이미지 서버가 없어서 Vercel 이미지 변환 한도(월 5,000건)도, 8192px 입력 제한도 적용되지 않는다.
4. **콘텐츠 검증이 내장이다.** Content Collections가 zod로 JSON 구조를 빌드 때 검증한다.
5. **CSP를 빌드가 만들어 준다.** 설정 `security.csp`가 페이지마다 스크립트와 스타일의 해시를 계산해 CSP에 넣는다. 정적 페이지에서도 `unsafe-inline` 없이 쓸 수 있다.
6. **React도 쓸 수 있다.** 꼭 필요한 부분만 React 섬(@astrojs/react 7.1.1)으로 넣을 수 있다. 기존 React 경험이 버려지지 않는다.

### Astro의 주의점

- **Astro에도 2026년 보안 공지가 여럿 있다.** 대부분 서버 렌더링(호스트 헤더 SSRF), 서버 아일랜드, 뷰 트랜지션 값 처리와 관련된 것이다(2차 출처 기준, 수정 버전은 6.3.3, 6.4.6, 7.0.4, 7.1.0). 정적 출력, 서버 아일랜드 미사용, ClientRouter 미사용으로 대부분 비켜 간다. 7.4.2는 위 수정 버전보다 새 버전이다. 적용 전에 공식 GitHub Security Advisory를 직접 확인한다.
- **익숙함은 Next.js가 앞선다.** 사용자의 기존 Vercel 프로젝트 대부분이 Next.js다. 이 항목이 결정적이라면 Next.js 16으로 가도 된다. 이 경우 `output: 'export'`로 정적 내보내기를 쓰고, 이미지 최적화는 끄고 빌드 때 만든 파일을 쓴다. 본 문서의 나머지 대부분은 그대로 적용된다.
- Astro 7은 Node 22.23.4 이상이 필요하다. 이 Mac의 Node는 24.17.0이라 충족한다.
- Astro의 CSP 기능은 ClientRouter와 Shiki 코드 강조를 지원하지 않는다. 이 프로젝트는 둘 다 쓰지 않는다.

### Next.js로 되돌려야 하는 신호

로그인, 관리자 화면, 결제, 실시간 갱신, 사용자별 개인화가 필요해지면 Next.js로 옮기는 것을 검토한다. 콘텐츠 JSON과 이미지는 프레임워크와 무관해서 옮길 때 그대로 쓴다.

## 2. 패키지 매니저 선택

| 후보 | 버전 | 설치 스크립트 | 신규 릴리스 대기 | Vercel 지원 |
|---|---|---|---|---|
| npm | 12.2.1 | 기본 `ignore-scripts=false`. 허용 목록 `allow-scripts`와 엄격 모드 `strict-allow-scripts`는 있으나 기본은 꺼짐 | `min-release-age`가 있지만 기본 꺼짐 | 지원 |
| **pnpm** | 12.15.0 | pnpm 10부터 의존성의 설치 스크립트 기본 차단. 허용 목록 `allowBuilds` | `minimumReleaseAge` 기본 1440분(24시간) | 6~12 지원 |
| Yarn | 4.18.1 | 확인하지 못함 | 한 2차 출처는 4.10부터 기본 켜짐이라고 함 | Vercel 문서 표는 1~3, 4는 Corepack으로 |
| Bun | 1.4.4 | `trustedDependencies`에 있는 것만 실행 | 초 단위 설정이 있음 | 지원 |
| vlt | 1.6.0 | 베타 | 확인하지 못함 | 베타 |

npm 12는 git과 원격 주소 의존성을 기본으로 막는 등 좋아졌지만, 설치 스크립트와 릴리스 대기가 기본으로 꺼져 있다. pnpm은 둘 다 기본으로 막는다. 이번 사이트는 공급망 공격을 방어 대상에 넣어야 하므로 **pnpm 12**를 쓴다. Bun은 빠르지만 런타임과 패키지 매니저를 같이 바꾸는 부담이 있고, 얻는 것은 속도뿐이다.

pnpm 설정 예시다. 키 이름은 설치한 버전의 문서로 다시 확인한다.

```yaml
# pnpm-workspace.yaml
minimumReleaseAge: 4320        # 3일. 기본 1일보다 길게
blockExoticSubdeps: true       # 하위 의존성이 git 주소나 임의 tarball이면 거부
trustPolicy: no-downgrade      # 신뢰 수준이 낮아진 패키지 거부
allowBuilds:                   # 설치 스크립트를 허용할 패키지만 나열
  sharp: true
  esbuild: true
```

- 이 Mac의 pnpm은 8.3.1로 오래됐다. `package.json`의 `packageManager` 필드에 12.x를 고정하고 Corepack으로 쓴다. Vercel도 이 필드를 따른다.
- 잠금 파일은 반드시 커밋하고, CI와 배포는 `pnpm install --frozen-lockfile`로만 설치한다.

## 5. 콘텐츠 파이프라인

기존 아카이브(iduk.design의 JSON)를 새 구조로 한 번 변환한다. 매번 도는 빌드 단계가 아니라 일회성 스크립트다.

1. **이미지 변환.** 실제로 쓰는 147장만 WebP로 바꾼다. 화질 90, 가로 2560px 상한.
   - 확인한 것: 흰 배경 한 점의 색 차이는 파란 채널 1(255 중)이고, 글자는 원본과 구별되지 않았다. 화질 82는 글자 주변이 약간 번져서 90으로 정했다.
   - 예상 용량은 약 25MB 이하. 시험 변환(화질 82)이 20MB였다.
   - 이름이 겹치는 3쌍은 확장자를 이름에 남긴다.
2. **본문 구조화.** 34개 글의 `dl.subject`에서 기간, 제목, 역할을 뽑고, 이미지는 등장 순서대로 블록 배열로 만든다. 나머지 7개는 수동.
3. **HTML 정화.** 옛 본문에는 `<style>` 블록과 `onclick` 속성이 있다(예: hidea 글의 버튼). 본문 HTML을 그대로 렌더링하지 않고, 구조화해서 필요한 요소만 새로 그린다. 남는 HTML은 sanitize-html 허용 목록을 통과시킨다.
4. **경로와 주소.** 새 이미지 경로로 모두 바꾸고, 옛 사이트와 CDN 주소는 남기지 않는다. 옛 주소에서 새 주소로 가는 리다이렉트 표를 만든다.
5. **스키마 검증.** zod로 검증한다. 깨진 이미지 참조, 빈 `alt`, 중복 슬러그가 있으면 실패한다.
6. **HTML 데모 복사.** `.DS_Store`, `.vscode`, 소스맵은 제외한다. 이 중 `.vscode/sftp.json`에 옛 다른 서버의 FTP 접속 정보(비밀번호는 비어 있음)가 있다. 공개 배포물에 넣지 않는다.

콘텐츠 스키마의 주요 필드는 다음과 같다.

| 필드 | 설명 |
|---|---|
| `slug`, `title`, `status` | 공개 상태는 public, private, draft |
| `period`, `year`, `order` | 기간과 정렬 |
| `role`, `summary`, `client` | 역할과 한 줄 설명 |
| `tags` | 태그 |
| `cover` | 대표 이미지(경로, alt, 가로, 세로, 평균색) |
| `blocks` | 이미지, 이미지 쌍, 긴 캡처, 글, 임베드 블록의 배열 |
| `links`, `demo` | 외부 링크와 HTML 데모 |
| `legacy` | 옛 글 번호와 주소 (리다이렉트용) |

## 6. 이미지 전략

- 마스터는 `src/assets/`에 둔다. `public/`에 두면 Astro가 처리하지 않는다.
- 화면에는 `<Picture>`로 AVIF와 WebP를 함께 낸다. 폭 후보는 640, 960, 1280, 1920, 2560. 원본보다 큰 폭은 만들지 않는다.
- 첫 화면의 이미지만 `fetchpriority="high"`와 즉시 로드. 나머지는 지연 로드.
- 모든 이미지에 가로와 세로를 지정해 레이아웃이 밀리지 않게 한다. 값은 `images.json`에서 온다.
- 긴 화면 캡처는 전용 컴포넌트가 장면을 보여 주고, 원본 높이 그대로의 큰 파일은 클릭할 때만 불러온다.
- 빌드 시간: 약 150장에 폭 5종, 형식 2종이면 1,500여 개 파일을 만든다. AVIF 인코딩이 느려서 첫 빌드가 몇 분 걸릴 수 있다(추정). 너무 오래 걸리면 WebP로 시작하고 AVIF는 나중에 추가한다.
- 변환본은 저장소에 커밋하지 않는다. 빌드 결과(`dist`)에만 생긴다.
- 의도적으로 쓰지 않는 것: Vercel 이미지 최적화(월 5,000건 변환 한도, 초과하면 새 이미지에서 402 오류), 원격 이미지(`image.domains`). 모두 로컬 파일이다.

## 8. 호스팅과 배포

Vercel Hobby 플랜 기준이다(2026-10-23 확인).

| 항목 | 한도 |
|---|---|
| 빠른 데이터 전송 | 월 100GB |
| CDN 요청 | 월 100만 건 |
| 함수 호출 | 월 100만 건 |
| 배포 | 하루 100회 |
| 런타임 로그 | 1시간 |
| 용도 | 비상업 개인용 |

- 정적 배포라 이 한도 대부분이 의미가 없다. 포트폴리오 이미지가 큰 편이라 데이터 전송량만 가끔 확인한다.
- 모든 풀 리퀘스트에 미리보기 주소가 생긴다. 공개 전 확인은 미리보기에서 한다.
- 분석은 Vercel Web Analytics(월 5만 이벤트)와 Speed Insights(최근 30일 1만 이벤트)를 쓴다. 같은 도메인에서 서비스되는 방식이라 CSP에 외부 주소를 추가하지 않는다. 설치 후 확인한다.
- 비공개 저장소도 연결할 수 있다.

## 9. 2단계: Neon

Neon이 필요한 기능만 넣는다. 콘텐츠 자체는 DB로 옮기지 않는다.

| 기능 | 필요한 이유 | 방식 |
|---|---|---|
| 문의 폼 | 연락처를 공개하지 않고 문의를 받으며 스팸을 걸러낸다 | 요청이 올 때만 실행되는 함수 하나 |
| 작업별 반응(좋아요) | 기존 워드프레스에 반응 기능이 있었다 | 함수 하나, 화면에서 비동기로 가져온다 |

기본 원칙은 다음과 같다.

- **DB를 페이지 렌더링 경로에 두지 않는다.** 페이지는 정적이고, 반응 수 같은 값만 화면에서 따로 가져온다. Neon 무료 플랜은 5분 동안 요청이 없으면 컴퓨트가 꺼져서 첫 요청이 느리다.
- 코드나 HTML을 DB에 저장하지 않는다. 이번 감염이 정확히 그 방식이었다.
- DB 권한을 둘로 나눈다. 앱용 역할은 필요한 테이블에 INSERT와 제한된 SELECT만, 마이그레이션 역할은 따로 둔다.
- 연결 정보는 Vercel 환경 변수(민감 값 설정)에만 둔다. 미리보기 배포는 Neon 브랜치로 격리한다.
- Neon 무료 플랜 한도(2026-10-23 확인): 프로젝트당 저장 1GB, 컴퓨트 100 CU-시간, 브랜치 10개, 복원 가능 기간 6시간. 한도를 넘으면 쓰기가 막히거나 컴퓨트가 멈추지만 데이터는 지워지지 않는다. 문의와 반응 수 정도로는 한참 못 미친다.
- 복원 기간이 6시간뿐이라서 주 1회 `pg_dump`를 따로 보관한다.

테이블 초안은 다음과 같다.

| 테이블 | 열 |
|---|---|
| `messages` | id, name, email, body, created_at, ip_hash, status |
| `reactions` | project_slug, kind, count |
| `reaction_votes` | project_slug, voter_hash, created_at (중복 방지, 원본 IP는 저장하지 않음) |

콘텐츠 관리를 웹 화면에서 하고 싶어지면 그때 3단계로 따로 계획한다. 코드를 실행하는 편집기는 만들지 않는다.
